# 航路规划候选点与可见图绕障机制说明

> **最后更新时间**：2026年9月16日

## 1. 概述与系统定位

在无人机三维智能航路规划（`AstarPathPlane` / `SmoothAstarPathPlane`）中，“**候选点 (Candidate Points)**”是连接宏观地理硬障碍绕飞与微观三维空间网格细分寻路的核心概念。

系统中的候选点主要包含两个层级：
1. **宏观二维活动可见图候选点 (Visibility Graph Detour Candidates)**：源自 PostgreSQL 空间拓扑图，专门用于大范围永久禁飞区、电子围栏、地面风险区与时效性临时电子围栏的水平绕行预规划，作为中继航路点注入规划队列；
2. **微观三维空间扩展候选网格 (3D Grid Search Candidate Nodes)**：位于 A* 启发式搜索主循环中，由父节点沿 26 邻域试探产生，并结合 3D 球形缓冲掩码进行异步批量环境通行性核验。

---

## 2. 二维活动可见图候选点机制 (Visibility Graph Candidates)

### 2.1 候选点数据源与拓扑结构

可见图候选点持久化于 PostgreSQL 数据库中，主要围绕城市关键管制区（`air_space`）、固定地理围栏（`fence`）以及地面高危区（`risk_area`）的外轮廓倒角顶点构建。

- **属性结构**：包含候选点唯一 ID、全球大地坐标 `[longitude, latitude]`、空间投影坐标 `[x, y]`（支持动态 SRID 投影转换）；
- **边拓扑连接**：各候选点之间通过经过离线可见性计算的连边（`edges`）相互连接，边属性记录了直连物理距离、穿过的潜在风险区域 ID 以及临时围栏 ID。

---

### 2.2 多阶段近邻筛选算法 (Multi-stage Expansion)

在调用 `VisibilityGraphPlanner::plan` 时，为了兼顾高并发实时响应性能与长航程绕障最优性，系统设计了**分阶段近邻启发式搜索机制**：

```
起点/终点 ──► 计算到全图所有候选点的平面欧几里得距离并排序 (startNearest / goalNearest)
          │
          ├──► 第 1 阶段：仅取前 32 个近邻候选点计算视线连通并寻路
          ├──► 第 2 阶段：未成功则扩大至前 64 个近邻候选点
          ├──► 第 3 阶段：未成功则扩大至前 128 个近邻候选点
          └──► 最终阶段：全量候选点兜底搜索
```

1. **视线可见性校验 (`visibilityCheck`)**：
   - 检验起点/终点到候选点、或候选点到候选点之间的连线是否与多边形障碍发生空间相交；
   - 结合任务开始时间戳 `startTime`，动态过滤当前处于生效时间窗内的 `temporary fence`（临时电子围栏）。
2. **双向 A* 图搜索**：
   - 维护优先队列，以直线欧氏距离作为启发式估计（$h$）；
   - 松弛各候选点之间的边（`relax`），快速求解绕过二维硬障碍的最短拓扑折线路径。

---

### 2.3 航路点动态注入与必经点属性 (Must-pass Protocol)

通过可见图求解出二维绕障折线后，系统将其作为中继航路点注入到 A* 的主航段规划任务中（`insertDatabaseVisibilityWaypoints`）：

1. **作业层高度继承**：
   - 可见图候选点本质为二维水平拐点，代码中明确遵循：
     ```cpp
     // 可见候选点只有经纬度，沿用当前航段作业层，不查询或写入地形高度。
     ```
   - 避免由于地表起伏突变引发航迹在拐点处产生剧烈的高度波动。
2. **必经点标记 (`mustPass`)**：
   - **`mustPass = true`**：前端用户在 API 中显式传入的航路起终点和中间必须途经的任务点；
   - **`mustPass = false`**：可见图算法自动在硬障碍外围计算并插入的临时绕行候选点。

---

### 2.4 抽稀阶段的分段区间锁定保护

在后续的贪婪视线平滑抽稀（`SmoothAstarPathPlane` / `thinPathGreedy`）中，`mustPass` 属性起到至关重要的安全防护作用：

- **区间锁定**：平滑抽稀算法**严格限制在相邻的 `mustPass = true` 必经点区间内部独立执行**；
- **防穿透保障**：如果允许整条航线全局抽稀，视线平滑算法可能会尝试将起点与终点直接拉直，从而把中间用于绕开禁飞区的候选点（`mustPass = false`）直接视线切角消除；通过必经点区间锁定，彻底杜绝了绕障拐点被抽稀误删导致航线穿入禁飞区的问题。

## 3. 三维 A* 空间扩展候选网格机制 (3D Grid Candidates)

在微观的三维空间搜索循环（`aStarPath`）中，候选点以网格为单元展开：

### 3.1 26 邻域候选试探与球形掩码映射

- **空间试探**：当前被访问的父网格节点向周围 26 个方向展开子代网格编码；
- **一对多体素簇展开**：每个子代候选点结合当前机型物理半径 `planeRadius` 生成的 `sphericalMask`（三维离散球形掩码），平移展开为包含自身及所有缓冲网格的**候选体素簇**（`candidateListForChecker`）。

### 3.2 异步并发通行性核验

- **协程批处理**：利用 C++20 协程（`co_await GridCheckAwaiter`），将所有展开的候选体素网格汇总，通过 Redis Pipeline 批量读取微气象、信号与环境因子数据；
- **极端阈值判定 (`threshold`)**：
  - 只要候选体素簇内任意一个网格的读数触碰了 `threshold`（如风速 $>13.8	ext{m/s}$ 或降水 $>8	ext{mm}$），该候选点直接被标记为不可通行（Hard Block）；
  - 记录明确的拒行日志（如 `"缓冲区检查失败: 邻居网格 ... 触及极端阈值"`）。
- **准入 OpenSet**：
  - 仅当候选点对应的球形缓冲掩码内**所有网格均合规**时，计算该候选点的移动距离代价、垂直升降代价及环境软代价；
  - 计算 $f = g + h$ 代价后，推入优先队列进行下一轮空间迭代。

## 4. 关键技术参数与交互速查

| 参数 / 属性 | 所在层次 | 核心作用 |
| :--- | :--- | :--- |
| `mustPass` | 航路点元属性 | `true` 为用户指定必经点，`false` 为可见图绕障候选点；约束平滑抽稀分段边界 |
| `planeRadius` | 空间物理属性 | 无人机物理半径，决定 3D 候选网格扩展时的球形防护掩码厚度 |
| `stages: [32, 64, 128]` | 可见图搜索参数 | 控制二维候选点近邻搜索规模，避免大规模全图爆搜造成接口超时 |
| `threshold` | 规则引擎属性 | 针对候选点各因子的极端阈值判定，触发即硬阻断候选点准入 |
