# 🛸 无人机航线规划系统 - 多权重算路与规则引擎配置指南

> **最后更新时间**：2026年9月16日

## 1. 核心评估模型 (Evaluation Model)

> 🚀 关于 A* 算法搜索流水线、26 邻域、仿地贴地及完整响应体解析，请参阅：
> 👉 [A星三维航路规划算法与接口使用文档.md](./A星三维航路规划算法与接口使用文档.md)


本系统采用基于 DQG-3D 离散网格的 A* 启发式空间搜索算法，在 3D 空间中，算法通过计算每个候选网格节点的**“总代价 (Total Cost)”**来寻找综合最优航线。

总代价的数学模型由物理距离代价、垂直高度变化效率代价以及多维度动态环境风险因子加权叠加构成：

$$TotalCost = DistanceCost + EfficiencyCost + \sum_{i=1}^{n} (FactorWeight_{i} 	imes FactorCost_{i})$$

- **$DistanceCost$**：空间三维欧几里得距离移动代价。
- **$EfficiencyCost$**：高度层升降惩罚代价（用于抑制无人机在巡航段频繁无意义爬升与俯冲）。
- **$FactorWeight_{i}$ (权重)**：系统对第 $i$ 类环境因子的敏感度。权重越高，算法越倾向于极力绕开该风险区域。
- **$FactorCost_{i}$ (代价)**：网格节点在该因子下的客观得分（范围为 `0.0` ~ `1.0`）。

### 1.1 极端阈值硬阻断机制 (`threshold`)

除了软性成本累加外，系统引入了 **`threshold`（极端阈值硬阻断）** 机制：
- 允许在因子配置中定义单条件或多条件阈值字符串，例如 `">13.8"`、`"<10 || >35"`、`"==1"`；
- 一旦某网格从 Redis 读到的实时数据触及该阈值条件，**无论该因子权重多小，该网格立即被标记为绝对不可通行（Hard Obstacle）**；
- 算法直接放弃扩展该网格节点，并记录失败原因（例如：`"风速 触及极端阈值限制(threshold)"`），从底层杜绝飞行器进入超风速、强雷暴或极温致命区域。

### 1.2 缓存未命中与默认代价策略

> [!IMPORTANT]
> **关于 `defaultValue` 的废除说明**：
> 早期版本中使用的 `defaultValue` 参数已被系统全面废弃并移除。当前系统中，若 Redis 中某网格未存储对应因子的数据，或者读到的数据未落在任何配置的 `value` 区间内，**系统默认赋予该因子的追加代价为 `0.0`**（不增加额外软代价），由 `threshold` 机制全权接管不可通行的安全硬阻断。

## 2. 算路模式预设 (Route Modes)

系统在 `weight.json` 中预置了四种宏观调优模式，可通过 API 请求体中的 `mode` 或 `route_type` 字段指定：

| 模式名称 | API 传参 | 核心控制策略 |
| :--- | :--- | :--- |
| **最短路径** | `"shortest"` | **效率极化**。大幅压低环境因子权重，在保证安全无碰撞前提下极力沿最短空间直线飞行。 |
| **风险最低** | `"safest"` | **安全极化**。大幅放大地面风险区（权重高达 2.0）、微气象（风/雨/能见度各 0.4）与升降代价，宁可增加航程也要最大化规避潜在风险。 |
| **综合最优** | `"balanced"` | **科学均衡**。兼顾航程能耗与飞行安全，对通信、导航、风险区和气象按黄金比例平权。 |
| **原始 A\*** | `"original"` | **纯几何寻路**。不加载环境软代价计算，以最低 CPU 耗时快速生成基础空间路径。 |

## 4. PostgreSQL 二维活动可见图绕障机制

系统内置了与 PostgreSQL 联动的 **二维活动可见图（Visibility Graph）绕行预处理引擎**：

1. **硬障碍数据源**：
   - 永久适飞与禁飞空域（`air_space` 表）；
   - 永久地理围栏（`fence` 表）；
   - 地面高危区域（`risk_area` 表）；
   - **时间窗口临时围栏（`temporary fence`）**：自动根据任务开始时间 `startTime` 匹配当前有效期的临时管制区。
2. **水平绕飞与必经点保持**：
   - 在进入 3D 空间细分搜索前，先在水平面针对上述硬多边形障碍进行可见性图搜索，获取绕行拐点；
   - 将绕行点动态作为航段中继点注入航线，原生起点与中继点标记为 `mustPass = true`，自动绕障点标记为 `mustPass = false`；
   - 航路平滑抽稀算法（`thinPathGreedy`）严格限制在相邻的 `mustPass` 必经点区间内独立执行，避免抽稀视线穿透禁飞区。
